# Оценки и пятничный отчёт

## Оценки

Администратор открывает «Загрузить оценки», выбирает PDF или XPS и учебный год, затем проверяет предварительный разбор. Программа группирует строки по предмету из заголовка журнала, показывает даты колонками и сопоставляет ФИО с активными пользователями группы. Строки без совпадения нужно исправить вручную либо явно исключить. Данные сохраняются только после подтверждения.

XPS с напечатанной таблицей распознаётся локально на сервере. В предпросмотре можно открыть изображение исходной страницы, исправить предмет, даты и отдельные оценки. Ячейки, которые программа не смогла распознать уверенно, нужно исправить или явно оставить пустыми до сохранения. Оригинальный файл и временные изображения удаляются после предпросмотра; в базе остаются только подтверждённые оценки и обычная запись об импорте. Повторная загрузка того же файла пропускается. Новая версия журнала обновляет совпадающие ячейки, но пустые клетки нового файла не удаляют ранее сохранённые оценки.

Администратор открывает «Оценки группы», выбирает ученика и видит компактную таблицу «Предмет | Оценки». У каждой оценки указана дата; кнопку «Скачать PDF для печати» можно использовать для отдельной ведомости этого ученика по всем предметам. PDF создаётся по запросу и не сохраняется на сервере. Студент открывает «Мои оценки» и видит только свои данные. Значение `нб` отображается как отсутствие, а не как числовая оценка. Доступ к чужим оценкам студенту не предоставляется.

Загруженный журнал и таблицы с персональными данными не добавляйте в публичный Git-репозиторий. Перед первым импортом проверьте предпросмотр на исходном файле: количество предметов, даты, ФИО, оценки и `нб`. Если расположение таблицы в другой версии файла отличается, импорт следует остановить до исправления разбора.

## Отчёт за неделю

Администратор и староста открывают «Отчёт», выбирают любую дату нужной недели и видят таблицу с фамилиями и часами отсутствия по дням с понедельника по субботу. Одна пропущенная пара считается как два часа. Уважительные часы обводятся кружком. Для занятий без отметки выводится `?`, чтобы их не приняли за ноль. Отменённые пары не учитываются. Таблицу можно распечатать или сохранить из браузера в PDF.

## Месячная ведомость пропусков

В разделе «Отчёт» есть ссылка на месячную ведомость. Для каждого дня показаны два столбца: неуважительные и уважительные часы. В конце строки — суммы за месяц; ведомость можно скачать в Excel. Данные из отметок по парам считаются по два часа за отсутствие. Если за день внесён итог с бумажной ведомости, в недельном и месячном отчётах используется этот итог. Он не меняет посещаемость конкретных пар. Для пары без отметки и без бумажного итога отображается `?`.

Импорт бумажных итогов запускается только из приватного JSON-файла с датами, ФИО и двумя массивами часов. Файл не хранится в репозитории. Команда `node apps/api/dist/scripts/import-daily-absence.js --check` читает JSON из стандартного ввода, проверяет все ФИО и числа и ничего не записывает. После резервной копии та же команда с `--apply` сохраняет новые дневные итоги. Повторный запуск с теми же данными безопасен; отличающиеся существующие итоги команда отклоняет.

## Excel-табель (.xls / .xlsx)

Администратор может загрузить табель академии, где студенты идут отдельными блоками, предметы строками, а числа месяца — столбцами. Импорт учитывает переход месяца (например, сентябрь → октябрь). «Н» преобразуется в «нб», записи вида «Н 5 Н» сохраняются как три отдельных отметки за день. Нераспознанные значения требуют ручной проверки. Невозможно сопоставленных студентов можно исключить только после явного подтверждения.

Повторная загрузка одного файла пропускается по контрольной сумме. При новой выгрузке уже существующие отметки сопоставляются по студенту, предмету, дате и порядковому номеру оценки внутри даты — независимо от расположения столбцов в PDF, XPS и Excel. Изменения обновляют прежнюю оценку, новые добавляются, пустые ячейки не удаляют старые записи. Перед сохранением проверьте предварительный просмотр.
