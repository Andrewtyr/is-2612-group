# MAX-бот группы ИС-2612

Бот встроен в существующий API сайта. Он показывает расписание на сегодня и завтра, замены и звонки. Для MAX ID старосты и заместителя доступны список группы, сводка посещаемости, синхронизация расписания и объявление в групповом чате. Команды `/id` и `/chatid` помогают получить нужные идентификаторы.

## Подготовка

Для рабочего режима нужен доступный `https://is2612.ru` с действующим сертификатом и созданный в MAX бот с токеном. MAX рекомендует webhook для работающего сервиса; polling предназначен для проверки. Токен и секрет храните только в `.env.production` на сервере, не добавляйте их в Git и не отправляйте в чат.

С сервера проверьте сайт:

```sh
curl -fsS https://is2612.ru/api/health
```

В ответ ожидается `{"status":"ok"}`. Если HTTPS ещё не настроен, сначала завершите настройку Nginx и сертификата.

## Включение на сервере

В `/opt/is-2612-group/.env.production` добавьте следующие строки. Получите секрет командой `openssl rand -hex 32` и вставьте полученное значение вместо примера. Токен берите из настроек созданного бота MAX.

```dotenv
MAX_BOT_TOKEN=токен_из_MAX
MAX_BOT_MODE=webhook
MAX_SITE_URL=https://is2612.ru
MAX_HEAD_USER_IDS=
MAX_GROUP_CHAT_ID=
MAX_WEBHOOK_URL=https://is2612.ru/api/max/webhook
MAX_WEBHOOK_SECRET=<вставьте_результат_openssl_rand_-hex_32>
MAX_MARKER_BINDINGS=
```

После сохранения настроек из корня проекта выполните:

```sh
sh scripts/deploy.sh
docker compose -f docker-compose.production.yml logs --tail=100 api
```

В журнале должна появиться запись `Webhook MAX настроен`. Публичный webhook без правильного заголовка `X-Max-Bot-Api-Secret` возвращает HTTP 401. Если токен или секрет не заданы, бот остаётся выключенным, а сайт продолжает работать.

## Права старосты и групповой чат

1. Напишите боту в личном диалоге `/id`.
2. Добавьте показанный числовой ID в `MAX_HEAD_USER_IDS`. Для нескольких пользователей разделите ID запятыми. Доступ по ID назначайте только после проверки владельца аккаунта MAX.
3. Добавьте бота в групповой чат MAX с правами, необходимыми для получения сообщений, и напишите в чате `/chatid`.
4. Добавьте полученный ID чата в `MAX_GROUP_CHAT_ID` без изменений, в том числе если он начинается с минуса.
5. Пересоздайте API-контейнер для применения переменных:

Если староста и заместитель оба отмечают группу через MAX, укажите соответствие `MAX user_id` и логина сайта в `MAX_MARKER_BINDINGS`, например `123456:is2612-07,987654:is2612-15`. Когда активный староста или заместитель один, связь определяется автоматически. ID добавляйте только после проверки владельца аккаунта MAX.

```sh
docker compose -f docker-compose.production.yml up -d --force-recreate api
```

После этого у старосты появится меню `⚙️ Староста`. Объявление отправляется только в чат, указанный в `MAX_GROUP_CHAT_ID`.

## Проверка и ограничения

- `/start` показывает меню; `/id` показывает личный MAX ID.
- Кнопка «Отметить группу» в меню старосты выбирает сегодняшнюю пару, затем студента. Можно поставить «Был», «Опоздал», «Нет», «Уважительная», «Освобождён», «Ушёл раньше» или «На проверке». Для отсутствия и уважительной причины бот предлагает категорию причины. Кнопка «Все неотмеченные были» требует подтверждения и не меняет уже выставленные отметки.
- Кнопки «Сегодня», «Завтра», «Замены» и «Звонки» читают существующую базу сайта.
- Если расписание пустое, проверьте синхронизацию академии на сайте.
- Если MAX временно недоступен при запуске, API повторяет регистрацию webhook через минуту.
- Массовой отметки каждого студента через MAX в этой версии нет; это делается на сайте.
- В Docker-образ API включён официальный сертификат `Russian Trusted Root CA` с портала Госуслуг, SHA-256 `D2:6D:2D:02:31:B7:C3:9F:92:CC:73:85:12:BA:54:10:35:19:E4:40:5D:68:B5:BD:70:3E:97:88:CA:8E:CF:31`. Проверка TLS не отключена.

Источники: [API MAX](https://dev.max.ru/docs-api), [webhook MAX](https://dev.max.ru/docs-api/methods/POST/subscriptions), [официальные сертификаты](https://www.gosuslugi.ru/crt).
